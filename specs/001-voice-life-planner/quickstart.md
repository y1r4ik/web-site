# Quickstart: запуск и проверка SGX PLANNER MVP

Руководство, чтобы развернуть MVP и пройти сценарии приёмки из [spec.md](./spec.md). Детали API
и бота — в [contracts/](./contracts/), структура данных — в [data-model.md](./data-model.md).

## Что нужно

- Node.js 24, Git, аккаунт Cloudflare (тариф Workers Free), Wrangler (`npx wrangler`).
- Бот @ezplaner_bot и его токен от @BotFather.
- Ваш Telegram ID (владелец) — узнать можно у бота после первого запуска или у @userinfobot.
- Для проверки из России — сеть, в которой открываются ресурсы Cloudflare (см.
  [research.md](./research.md), раздел о сетевых ограничениях).

## Первое развёртывание

```bash
npm install

# Ресурсы Cloudflare (один раз). Выведенные id вписать в wrangler.jsonc
npx wrangler login
npx wrangler d1 create sgx-planner
npx wrangler kv namespace create MEDIA
npx wrangler queues create sgx-inputs

# Секреты (вводятся интерактивно, в репозиторий не попадают — принцип IV)
npx wrangler secret put BOT_TOKEN
npx wrangler secret put WEBHOOK_SECRET
npx wrangler secret put OWNER_TELEGRAM_ID

# Миграции базы и деплой (сборка Mini App + Worker)
npm run db:migrate:remote
npm run deploy

# Регистрация вебхука, кнопки меню и команд бота
npm run bot:setup
```

В @BotFather: `/setdomain` не нужен; Mini App подключается кнопкой меню, которую выставляет
`bot:setup`. Для прямой ссылки можно создать Mini App командой `/newapp` с тем же URL.

## Локальная разработка

```bash
npm run dev          # Next.js — вёрстка Mini App с моками API (без Telegram)
npm run worker:dev   # Worker локально (wrangler dev), D1 и KV — локальные копии
npm test             # unit-тесты (Vitest)
npm run check        # lint + typecheck + test + build — то же, что в CI
```

Для проверки внутри Telegram нужен HTTPS-адрес: удобнее всего деплой в отдельное окружение
`npm run deploy:staging` со своим тестовым ботом.

## Сценарии проверки

| # | Сценарий | Ожидаемый результат | Требования |
|---|---|---|---|
| 1 | Написать боту с аккаунта не из списка | ответ о закрытом тесте с ID; в базе ничего не появилось | FR-003, US1-8 |
| 2 | Владелец: `/allow <ID>`; тестировщик жмёт `/start` | приветствие, пример фразы, вопрос о часовом поясе | FR-002, FR-003a, US1-1 |
| 3 | Голосовое: «завтра в 10 созвон с Лёшей, купить молоко, на обед съел борщ и хлеб, день был тяжёлый, но продуктивный» | итог с 4 записями ≤ 15 с; кнопки «Отменить», «Открыть и исправить» | US1-2, FR-010, SC-002 |
| 4 | Нажать «Отменить» | итог превращается в «Отменено», записей в ленте нет | US1-3, FR-011 |
| 5 | «в пятницу созвон с отделом» | встреча-черновик, в итоге строка «Уточните» | US1-6, FR-008 |
| 6 | Mini App → кнопка записи → та же фраза | итог в Mini App, записи те же, что в п. 3 | US1-9, FR-004a |
| 7 | Mini App: отметить задачу, поменять время встречи, удалить запись, перейти на вчера | изменения сохраняются после перезапуска | US2-2…5 |
| 8 | Отправить боту фото тарелки с подписью «ужин» | ужин с позициями, граммами, ккал и КБЖУ | US3-1, US3-2 |
| 9 | Отправить фото без еды | «Не нашёл еды на фото», запись не создана | US3-3, FR-015 |
| 10 | Создать встречу через 20 минут | напоминание за 15 минут, ±1 мин | US4-1, SC-006 |
| 11 | Изменить время этой встречи, затем удалить её | напоминание по новому времени; после удаления — нет | US4-2, US4-3 |
| 12 | Настройки: норма 2000 ккал, пояс, «Удалить все мои данные» | прогресс калорий в ленте; после удаления бот начинает со старта | US5-1…3 |
| 13 | Запрос к `/api/day` с подделанным `initData` или чужим id записи | `401` / `404`, данные не выданы | FR-033, SC-007 |

## Проверка качества ИИ

```bash
npm run eval -- --set phrases   # SC-003: доля верных типов записей и дат встреч
npm run eval -- --set photos    # SC-004: доля фото с ошибкой калорий ≤ 25 %
```

Прогон тратит бесплатный дневной бюджет Workers AI — запускать вручную, не в CI.
